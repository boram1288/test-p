# Secure Vision AI 레퍼런스 시나리오

## 1. 시나리오 목적

비신뢰 Host 환경에서 Camera 영상과 AI 자산을 보호하면서 Camera HW와 AI HW의 가속
성능을 사용하는 Secure Vision AI 시나리오를 정의한다.

차량 Camera 영상을 보호된 Camera pVM에서 수집하고, 보호된 AI pVM으로 전달해 AI
추론을 수행한다. 원본 영상, AI model, 중간 데이터와 암호화 키는 비신뢰 Host에
노출하지 않고 공개 가능한 추론 결과만 Host App에 반환한다.

## 2. 고객 요구사항

| ID | 요구사항 | 구조적 반영 |
|---|---|---|
| R-1 | 영상 및 AI IP 자산 보호 | Camera와 AI workload를 별도 pVM으로 격리 |
| R-2 | 고성능 HW 가속 지원 | Camera HW와 AI HW를 각 pVM workload가 직접 사용 |
| R-3 | 유럽향 시나리오 지원 | 차량 안전 및 AI 관련 EU 규제 고려 |
| R-4 | GlobalPlatform 표준 준수 | TEE의 Crypto Manager와 표준 보안 API 사용 |

보안 법규는 다음과 같이 해석한다.

- Regulation (EU) 2019/2144는 차량과 관련 시스템의 일반 안전 형식승인 요구사항이다.
- AI 관련 규정은 Regulation (EU) 2024/1689, 즉 AI Act다.

공식 근거:

- [Regulation (EU) 2019/2144](https://eur-lex.europa.eu/eli/reg/2019/2144/2024-07-07/eng)
- [Regulation (EU) 2024/1689](https://eur-lex.europa.eu/eli/reg/2024/1689/oj/eng)

## 3. 보호 대상 자산

- Camera sensor 원본 영상
- Camera pVM에서 AI pVM으로 전달되는 frame
- AI 입력 데이터와 중간 tensor
- AI model과 model 검증 파일
- 복호화된 model
- 암호화 키와 신뢰 anchor
- pVM 내부 DMA-BUF metadata와 local reference
- AI 추론 과정의 중간 상태

## 5. 신뢰 경계

### 5.1 비신뢰 REE

Host App, Camera Service와 AI Service는 orchestration을 수행하지만 frame payload,
복호화된 model과 암호화 키를 신뢰 상태로 읽지 못한다.

### 5.2 Camera pVM

Camera HW가 생성한 원본 frame을 보호 메모리에 저장한다. Camera pVM은 local DMA-BUF
exporter 역할을 수행한다.

### 5.3 AI pVM

보호 handle을 AI local proxy DMA-BUF로 가져오고 검증된 model로 추론을 수행한다.

### 5.4 TEE

Crypto Manager, 키와 신뢰 anchor를 보호한다. model 복호화와 서명·무결성 검증을
수행한다.

### 5.5 장치 DMA 경계

pVM의 CPU memory isolation과 장치 DMA isolation을 분리해 관리한다. Stage-2 mapping은
pVM CPU 접근을 제어하고 SMMU/IOMMU mapping은 Camera HW와 AI HW의 DMA 접근을 제어한다.

## 6. 시나리오 사전 조건

- Camera pVM과 AI pVM을 실행할 수 있다.
- Camera HW와 AI HW가 승인된 pVM에 연결되어 있다.
- Camera와 AI 장치의 SMMU/IOMMU 격리가 활성화되어 있다.
- AI model과 model 검증 파일이 저장되어 있다.
- Crypto Manager에 필요한 키와 신뢰 anchor가 준비되어 있다.
- REE, pVM과 TEE 사이 memory isolation이 설정되어 있다.
- Cross-pVM DMA-BUF Bridge가 handle과 endpoint generation을 발급할 수 있다.

## 7. 정상 시나리오

### 7.1 그림 기반 축약 정상 시나리오

1. Host App이 Camera Service와 AI Service를 동적으로 실행한다.
2. Camera Service가 pVM의 Camera Stream Workload를 실행한다.
3. Camera Stream Workload가 Camera HW를 사용해 Sensor Data를 수집한다.
4. 수집된 영상은 메모리 격리를 유지하며 AI pVM의 AI 추론 Workload로 전달된다.
5. AI 추론 Workload가 model 및 model 검증 파일을 사용하고 AI HW로 추론을 수행한다.
6. 필요한 암복호화 기능은 World 격리를 거쳐 TEE의 Crypto Manager를 사용한다.
7. AI 추론 결과는 출력 결과 관리 경로를 통해 Host App으로 반환된다.

### 7.2 서비스 및 pVM 시작

1. 사용자가 Host App에 Secure Vision AI 기능 실행을 요청한다.
2. Host App이 Camera Service와 AI Service를 동적으로 실행한다.
3. Camera Service가 Camera Stream Workload를 Camera pVM에서 시작한다.
4. AI Service가 AI 추론 Workload를 AI pVM에서 시작한다.
5. Camera pVM과 AI pVM의 endpoint generation을 등록한다.

### 7.3 Camera frame 생성

1. Camera pVM이 Camera HW 사용 권한과 DMA mapping을 획득한다.
2. Camera Stream Workload가 local DMA-BUF를 준비한다.
3. Camera HW가 sensor frame을 보호 backing page에 DMA write한다.
4. Camera producer fence가 완료된다.
5. Camera pVM이 frame metadata와 producer fence를 export한다.

### 7.4 Cross-pVM frame 전달

1. Cross-pVM DMA-BUF Bridge가 Camera local DMA-BUF를 protected handle로 표현한다.
2. Bridge가 buffer generation, Camera generation과 허용 AI endpoint를 기록한다.
3. Camera workload가 protected handle, metadata와 producer fence를 AI workload에 알린다.
4. AI proxy importer가 protected handle을 redeem한다.
5. Bridge가 AI pVM과 AI HW에 필요한 Stage-2 및 SMMU/IOMMU mapping을 승인한다.
6. AI pVM이 동일 backing page를 가리키는 local proxy DMA-BUF를 만든다.
7. Bridge가 Camera producer fence를 AI local fence로 변환한다.

### 7.5 Model 검증과 AI 추론

1. AI workload가 Model 저장소에서 암호화된 model과 검증 파일을 읽는다.
2. AI workload가 Crypto Manager에 model 검증을 요청한다.
3. Crypto Manager가 model의 서명, 무결성과 사용 권한을 검증한다.
4. 필요한 경우 TEE의 키를 이용해 model을 복호화한다.
5. 검증에 성공하면 AI workload가 AI local fence 완료를 기다린다.
6. AI workload가 보호 frame과 검증된 model을 AI HW에 제출한다.
7. AI HW가 동일 보호 backing page를 DMA read하고 추론을 수행한다.
8. AI HW가 consumer fence와 추론 결과를 AI workload에 반환한다.

### 7.6 결과 반환과 buffer 회수

1. AI workload가 공개 가능한 추론 결과만 AI Service에 반환한다.
2. AI Service가 정제된 결과를 Host App에 전달한다.
3. 원본 frame, 중간 tensor, 복호화된 model과 키는 Host에 반환하지 않는다.
4. AI proxy DMA-BUF의 최종 local reference를 해제한다.
5. Bridge가 AI remote lease와 mapping을 해제한다.
6. Camera와 AI의 local reference, Bridge lease와 device DMA 완료를 확인한다.
7. backing page를 재사용하거나 안전하게 해제한다.

## 8. DMA-BUF 전달 모델

Camera와 AI pVM은 서로 다른 Linux kernel instance이므로 fd, `struct dma_buf`,
`dma_resv`와 reference count를 공유하지 않는다.

```text
Camera pVM
  Camera local DMA-BUF
  fd + struct dma_buf + local dma_resv
             |
             | export
             v
Cross-pVM DMA-BUF Bridge
  protected handle
  frame metadata
  buffer/endpoint generation
  producer fence translation
  cross-pVM remote lease
             |
             | redeem
             v
AI pVM
  AI proxy DMA-BUF
  fd + struct dma_buf + local dma_resv
```

수명 규칙은 다음과 같다.

- 각 pVM 내부 객체의 수명은 local DMA-BUF reference count로 관리한다.
- kernel 경계를 넘는 수명은 Bridge remote lease로 관리한다.
- Bridge lease는 local reference count의 복제본이 아니다.
- producer fence 완료 전 AI job을 제출하지 않는다.
- consumer DMA 완료 전 buffer를 재사용하지 않는다.
- fence 완료와 reference 해제를 같은 사건으로 처리하지 않는다.
- pVM crash 시 generation을 폐기하고 remote lease와 mapping을 강제로 정리한다.

## 9. 보안 요구사항

### 9.1 Host 비노출

- Host의 frame payload mapping/read 성공은 0회여야 한다.
- Host가 Camera 또는 AI 장치의 DMA mapping을 변경하지 못해야 한다.
- Host에는 공개 가능한 추론 결과만 반환한다.

### 9.2 pVM 간 최소 권한

- Camera pVM은 frame write 권한을 갖는다.
- AI pVM은 producer fence 완료 후 frame read 권한을 사용한다.
- 미등록 pVM의 protected handle redeem과 mapping을 거부한다.
- stale buffer와 endpoint generation을 거부한다.

### 9.3 Model과 키 보호

- 암호화되지 않았거나 검증되지 않은 model loading을 거부한다.
- model 서명과 무결성 검증에 실패하면 AI 추론을 시작하지 않는다.
- 복호화 키와 신뢰 anchor는 TEE 밖으로 노출하지 않는다.
- 복호화된 model의 Host mapping을 금지한다.

## 10. 예외 및 장애 시나리오

| 장애 | 처리 원칙 |
|---|---|
| Camera pVM 시작 실패 | AI 추론 시작을 취소하고 Host에 오류 반환 |
| AI pVM 시작 실패 | Camera capture 중지 및 보호 buffer 회수 |
| Camera HW 오류 | 진행 중 frame 오류 처리와 신규 capture 차단 |
| AI HW 오류 | 해당 frame 격리 후 AI HW reset 또는 승인된 대체 경로 실행 |
| producer fence timeout | AI HW에 frame을 제출하지 않고 해당 buffer 격리 |
| consumer fence timeout | buffer 재사용을 중지하고 AI DMA 정지 확인 |
| Camera pVM crash | Camera generation 폐기, remote lease와 mapping 강제 정리 |
| AI pVM crash | AI generation의 proxy, remote lease와 mapping 강제 정리 |
| model 검증 실패 | model loading과 AI 추론 거부 |
| 암호화 키 획득 실패 | model 복호화와 AI 추론 거부 |
| forged/stale handle | redeem과 mapping 거부 및 보안 이벤트 기록 |
| Host의 frame 접근 시도 | Stage-2와 SMMU/IOMMU 정책으로 차단 |

장치 DMA가 진행 중일 가능성이 있으면 DMA quiesce 또는 device reset을 확인하기 전에
mapping을 제거하거나 backing page를 free하지 않는다.

## 11. 시나리오 완료 조건

- AI 추론 결과가 정책에 따라 Host App에 반환되었다.
- 원본 frame과 AI 자산이 Host에 노출되지 않았다.
- 완료된 frame의 local reference와 Bridge remote lease가 정리되었다.
- Camera와 AI 장치의 DMA 작업이 완료되었다.
- 재사용 대상 buffer가 안전한 상태로 반환되었다.
- 종료 대상 pVM과 장치 mapping이 안전하게 해제되었다.

## 12. 추가 상세 설계 항목

- DMA-BUF pool 생성과 allocation authority
- Cross-pVM DMA-BUF Bridge의 실행 위치
- protected handle과 generation의 bit layout
- producer/consumer fence translation protocol
- Stage-2와 SMMU/IOMMU mapping 책임
- frame drop, queue depth와 backpressure 정책
- pVM crash 시 device quiesce와 forced detach 절차
- Host에 공개할 AI 결과의 filtering 정책
- model key provisioning, rotation과 revoke 절차
- GlobalPlatform API와 profile 선택
- model update와 rollback protection
- 감사 로그의 저장 위치와 보호 방법

## 13. 시나리오 요약

> 비신뢰 Host가 Camera와 AI 서비스를 orchestration하되, 원본 영상과 AI 자산은 Camera
> pVM, AI pVM 및 TEE 내부에서만 처리한다. Camera pVM의 local DMA-BUF는 Cross-pVM
> DMA-BUF Bridge의 protected handle, metadata와 fence를 통해 AI pVM의 local proxy
> DMA-BUF에 연결한다. 검증된 model과 보호 frame을 HW 가속기에 제공하고 공개 가능한
> 추론 결과만 Host로 반환한다.
