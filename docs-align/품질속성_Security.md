# 보안 품질속성에 4나인 / 5나인 메트릭 적용 가능 여부

보안 품질속성에 **4나인(99.99%)**, **5나인(99.999%)** 메트릭을 적용하는 것은 가능하지만,  
보안 품질속성 전체에 직접 적용하는 것은 일반적으로 적절하지 않습니다.

`99.99%`, `99.999%`와 같은 **나인(nines)** 지표는 본래 **가용성(Availability)** 을 표현하는 데 가장 적합한 메트릭입니다.

## 품질속성별 적용 가능성

| 품질속성 | 4나인/5나인 적용 | 예 |
|---|---|---|
| Availability | 매우 적합 | 보안 인증 서비스 가용성 ≥ 99.999% |
| Confidentiality | 부적합 | "기밀성 99.999%"는 의미가 모호 |
| Integrity | 조건부 가능 | 정상 데이터 무결성 유지율 ≥ 99.999% |
| Authenticity | 조건부 가능 | 정상 인증 성공률 ≥ 99.999% |
| Accountability | 일반적으로 다른 지표 사용 | 보안 이벤트 감사로그 기록률 = 100% |
| Non-repudiation | 일반적으로 다른 지표 사용 | 중요 명령 서명 검증률 = 100% |

## 보안에 나인 메트릭을 직접 적용할 때의 문제

보안에서는 다음과 같이 표현하는 것이 적절하지 않을 수 있습니다.

> 시스템의 보안 수준은 99.999%이다.

이 표현은 보안 수준이 정확히 무엇을 의미하는지 불분명합니다.

보안 사고는 단순 발생 확률뿐 아니라 다음 요소들이 중요하기 때문입니다.

- 공격 성공 가능성
- 취약점 재현 가능성
- 공격의 영향도
- 탐지 가능성
- 대응 시간
- 피해 확산 범위

예를 들어 인증 우회가 100만 건 중 1건 발생한다고 하더라도, 공격자가 그 1건의 취약점을 반복적으로 재현할 수 있다면 매우 심각한 보안 취약점입니다.

따라서 단순히 `99.9999% 안전하다`고 표현하는 것은 보안 수준을 정확하게 나타내지 못할 수 있습니다.

## 보안 품질속성에 적합한 정량 메트릭

보안 품질속성에서는 다음과 같은 메트릭을 사용하는 것이 더 적절합니다.

| ISO/IEC 25010:2023 Quality Attribute | 메트릭 | 정량 기준 |
|---|---|---|
| Security — Confidentiality, Resistance | 공격 차단률 | 탐지된 비인가 접근 차단율 ≥ 99.99% |
| Security — Authenticity | 인증 정확도 | 정상 사용자 인증 성공률 ≥ 99.999% |
| Security — Integrity | 무결성 검증률 | 중요 메시지 및 명령 무결성 검증률 = 100% |
| Security — Resistance | 보안 이벤트 탐지 시간 | 공격 발생 후 3초 이내 탐지 |
| Security — Resistance | 격리 시간 | 보안 침해 탐지 후 5초 이내 해당 노드 격리 |
| Security — Resistance / Reliability — Recoverability | 복구 시간 | 침해 노드 격리 후 정상 서비스 복구 ≤ 30초 |
| Security — Resistance | 취약점 관리 | Critical 취약점 발견 후 24시간 이내 조치 |
| Security — Accountability | 보안 로그 완전성 | 중요 보안 이벤트 기록률 = 100% |

## Availability와 Security의 차이

### Availability

질문:

> 서비스가 정상적으로 사용할 수 있는 상태인가?

대표 KPI:

- 서비스 가용성
- 장애 시간
- MTBF
- MTTR

따라서 다음과 같은 나인 메트릭을 직접 사용할 수 있습니다.

- 3-nine: 99.9%
- 4-nine: 99.99%
- 5-nine: 99.999%

### Security

질문:

> 공격을 얼마나 잘 방어하고, 탐지하고, 대응할 수 있는가?

대표 KPI:

- 공격 탐지율
- 공격 차단율
- MTTD (Mean Time To Detect)
- MTTC (Mean Time To Contain)
- 인증 성공률
- 무결성 검증률
- 보안 이벤트 기록률
- 취약점 대응 시간

따라서 보안에서는 하나의 나인 값보다는 여러 개의 정량 메트릭을 조합하는 것이 적절합니다.

## 권장 방식

아키텍처 품질속성을 정의할 때 다음과 같은 방식이 적절합니다.

### 권장하지 않는 표현

```text
Security = 99.999%
또는
보안 수준 = 5-nine
```

### 권장하는 표현

Security:

- 비인가 명령 차단율 ≥ 99.999%
- 중요 명령 무결성 검증률 = 100%
- 보안 공격 탐지 시간 ≤ 3초
- 침해 노드 격리 시간 ≤ 5초
- Critical 취약점 조치 시간 ≤ 24시간
- 보안 인증 서비스 가용성 ≥ 99.999%
