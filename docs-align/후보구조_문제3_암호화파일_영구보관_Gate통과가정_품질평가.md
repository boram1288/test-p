# 문제 3 후보 구조 품질 평가 — 모든 Gate 통과 가정

## 1. 평가 목적

이 문서는 [문제 3 후보 구조](후보구조_문제3_암호화파일_영구보관.md)의 두 후보가 모든 필수 Gate와
실현 가능성 Gate를 통과했다고 가정하고 품질 특성을 비교한 별도 시나리오 평가다.

이 평가는 실제 Gate 검증 완료를 뜻하지 않는다. 원문에서 `확인 필요`인 상태를 바꾸지 않으며,
[후보 구조 품질 평가 규칙](후보_구조_품질_평가_규칙.md)에 따라 Gate와 KPI 별점을 분리한다.

## 2. 평가 대상과 가정

### 2.1 평가 대상

- **후보 A:** Host 공용 영구 저장 서비스가 암호문 이름 공간, 파일 I/O와 저장 수명을 통합 관리한다.
- **후보 B:** Framework는 Workload별 볼륨 수명만 관리하고 pVM 저장 서비스가 파일 I/O를 담당한다.

### 2.2 모든 Gate 통과 가정

이 문서에서만 다음 항목이 두 후보 모두 `통과(가정)`했다고 본다.

1. 최신 committed 파일 복구 성공률 100%
2. 저장 경로의 키·평문 노출 0건
3. 다른 Workload의 오연결·파일 접근 성공 0건
4. 중복 mount, 불완전 commit 확정과 연결 metadata 누락 0건
5. `T_reclaim` 이후 고아 볼륨 0개·0 MB
6. 신규 Workload 저장 정책 추가 시 Framework 코어 변경 0 LoC
7. 비-RPMB 저장소의 삭제·변조·되돌리기 공격 검출률 100%
8. 후보 A의 이름 공간 유지·재연결, Workload별 자원 격리, TEE 검증과 쓰기 복구 실현 가능성
9. 후보 B의 볼륨 수명 제어, pVM 파일 I/O, detach·reclaim, 코어 무수정 자동화와 동시 attach 차단 실현 가능성

M-04d는 아직 정의되지 않은 비-RPMB 검출 메커니즘이 존재하고 정상 동작한다고 가정한 항목이다.
그 메커니즘의 실행 위치, 저장 overhead와 코드 변경량에 미치는 후속 영향은 이 평가 범위에 포함하지 않는다.

### 2.3 가정하지 않는 항목

- KPI 실측값과 대표 PoC 결과
- 승인된 KPI 별점 구간
- 제품 SLO와 품질속성 우선순위·가중치
- 후보 A의 공용 서비스 복제·failover
- 후보 B의 공용 볼륨 관리자 이중화·상태 복구

따라서 아래의 별점은 모두 `모든 Gate 통과 가정`에 따른 구조 휴리스틱이며 확정 KPI 별점이 아니다.

`통과(가정)`은 품질 평가 규칙의 정식 판정값을 추가한 것이 아니라 이 시나리오에서만 사용하는 표시다.
원문 Gate의 정식 판정은 실제 검증 전까지 `확인 필요`로 유지된다.

## 3. 평가 원칙

1. Gate 통과는 후보의 최소 선택 자격을 확보한다는 의미다.
2. 이진 판정만 가능한 보안성·신뢰성 Gate에는 정도 차이를 측정하는 KPI가 없으므로 별점을 부여하지 않는다.
3. Gate와 연속형 KPI를 함께 가진 품질속성은 Gate 통과 후 KPI의 정도 차이를 별도로 평가할 수 있다.
4. 실측값과 승인된 별점 구간이 없으므로 `잠정 ★☆☆`부터 `잠정 ★★★`까지만 사용한다.
5. 같은 잠정 구간 안의 구조적 차이는 `방향상 우세`로만 표현하며 점수 차이로 확대하지 않는다.
6. 승인된 가중치가 없으므로 평균, 합계와 전체 총점을 계산하지 않는다.

별점은 원문의 구조 휴리스틱 기준을 그대로 적용한다.

| 예상 별점 | 구조 휴리스틱 기준 |
|---|---|
| 잠정 ★★★ | 후보를 가르는 메커니즘과 필요한 완화책이 구조에 포함되고 직접 비교 가능한 사례나 분석이 있음 |
| 잠정 ★★☆ | 구조적 방향과 유사 사례는 있으나 프로젝트별 자동화·HA·운영 검증 또는 직접 비교 근거가 더 필요함 |
| 잠정 ★☆☆ | 공유 핵심 경로나 장애 집중 위험이 남고 이를 줄일 완화 메커니즘이 구조에 없음 |

### 4.2 후보별 실현 가능성 Gate

| 후보 | 통과를 가정한 범위 | 결과와 남는 불확실성 |
|---|---|---|
| A | pVM 수명과 독립적인 이름 공간, Workload별 자원 격리, TEE 검증, 공용 서비스 재시작 후 쓰기 복구 | 구조 실현 가능성은 확보한 것으로 본다. 공용 서비스 자체의 복제·failover와 MTTR은 가정하지 않는다 |

이 시나리오에서는 두 후보 모두 Gate로 탈락하지 않으며 품질 KPI 비교 대상으로 남는다.

데이터 경로 분리의 효과·완화책을 설명하는 데만 사용한다. 외부 시스템의 수치는 이 별점의 KPI 값으로 사용하지 않는다.

## 6. 종합 결과 — 모든 Gate 통과 가정, 확정 선택 아님

### 6.1 품질 프로파일

| 평가 관점 | 결과 |
|---|---|
| 최소 선택 자격 | 모든 Gate 통과 가정에 따라 A와 B 모두 확보 |
| 보안성·신뢰성 | 두 후보 모두 필수 기준을 충족한다고 가정. 이진 Gate만으로 후보 간 정도 차이는 판단하지 않음 |
| 성능 | 두 후보 모두 잠정 ★★☆. A가 재연결 단계 수 측면에서 방향상 우세 |
| 자원 효율 | 두 후보 모두 잠정 ★★☆. A가 공용 자원 공유 측면에서 방향상 우세 |
| 가용성 | M-06c·M-06d에서 A 잠정 ★☆☆, B 잠정 ★★☆. B가 장애 경계 분리 측면에서 방향상 우세 |
| 확장성 | 두 후보 모두 잠정 ★★☆. M-08b는 A가 방향상 우세하고 M-08c는 우열 판단 불가 |

### 6.2 해석

- **후보 A**는 모든 Gate를 통과해도 파일 I/O가 공용 서비스에 집중된다는 구조적 특성이 남는다.
  cold start, Workload당 자원과 통합 리드타임에서는 방향상 유리하지만 가용성 위험을 줄일 HA 구조는 별도 결정이 필요하다.
- **후보 B**는 모든 Gate를 통과하면 볼륨 수명과 파일 I/O 분리가 실제로 동작한다는 전제가 확보된다.
  Workload별 장애 경계 때문에 가용성에서 방향상 유리하지만 attach 단계, 중복 자원과 공용 볼륨 관리자 위험은 남는다.
- 잠정 별점 구간이 실제로 갈리는 항목은 M-06c와 M-06d뿐이다.
  나머지 항목의 방향상 우세는 KPI 실측 전에는 후보 선택을 확정할 정도의 차이로 보지 않는다.

### 6.3 조건별 판단

| 우선 조건 | 품질 관점의 조건부 판단 |
|---|---|
| 여러 Workload의 독립 가용성과 장애 영향 제한이 최우선 | 후보 B가 방향상 유리 |
| cold start, Workload당 저장 자원과 통합 공수 최소화가 최우선 | 후보 A가 방향상 유리하지만 동일 잠정 별점 구간이므로 실측 후 판단 필요 |
| 우선순위·가중치가 정해지지 않음 | 전체 우승 후보와 총점을 정하지 않음 |

이 결과만으로 후보를 확정 선택하지 않는다. 모든 Gate 통과 가정은 선택 자격을 열어 줄 뿐이며,
품질 우선순위와 KPI 근거를 대신하지 않는다.

## 7. Claude 반론 검토와 반영 결과

Codex가 평가 초안을 작성하고 Claude가 규칙 위반과 과대평가 가능성을 반론 관점에서 검토했다.
Claude는 파일을 수정하지 않고 다음 의견을 제시했으며, Codex가 최종 문서에 반영했다.

| Claude의 반론 | 검토 결과 | 반영 내용 |
|---|---|---|
| 가정 평가가 실제 Gate 검증 완료로 오인될 수 있음 | 타당 | 제목, Gate 표와 KPI 표에 `모든 Gate 통과 가정`, `실제 검증 아님`을 반복 표기 |
| 후보 A의 Workload별 격리 Gate가 통과했다면 `quota·partition 부재`를 M-06c 약점으로 쓸 수 없음 | 타당 | 해당 근거를 제거하고 공용 I/O 경로와 복제·failover 미확인만 남김 |
| Gate 통과 자체를 별점 없음의 이유로 일반화하면 안 됨 | 타당 | 보안성·신뢰성 항목이 이진 판정이고 연속 KPI가 없기 때문에 별점이 없다고 명시 |
| M-04d는 아직 없는 메커니즘의 존재를 가정하므로 다른 KPI에 미칠 영향을 분리해야 함 | 타당 | 메커니즘의 실행 위치·overhead·코드 영향은 평가 범위 밖이라고 명시 |
| B의 가용성 우세만 확정적으로 표현하면 잠정 점수의 한계와 모순됨 | 타당 | A와 B의 모든 비교 결론을 `방향상 우세`로 통일 |

Claude 검토 후 별점 숫자는 유지했다. 반론은 Gate 통과 가정과 충돌하는 근거를 제거하고 결과 표현의 확정도를 낮추는 데 반영했다.

## 8. 확정 평가로 전환하기 위한 검증

1. M-04d 메커니즘의 실행 위치와 추가 저장량·코드 변경량을 확정한다.
2. 같은 pVM 이미지와 부하에서 M-01d 평균·p95·최댓값을 측정한다.
3. Workload 수와 파일 수를 같은 단계로 늘리며 M-02c를 측정한다.
4. 공용 서비스, 특정 볼륨과 볼륨 관리자 장애를 각각 주입해 M-06c와 M-06d를 측정한다.
5. 같은 숙련도와 완료 조건으로 M-08b·M-08c를 반복 측정한다.
6. 측정 전에 KPI 별점 구간과 품질속성 우선순위·가중치를 승인한다.

측정값이 승인된 구간에 배치된 뒤에만 잠정 별점을 확정 별점으로 교체한다.
전체 총점이나 최종 후보 선택은 사용자가 우선순위와 집계 기준을 승인한 경우에만 작성한다.
