# Architecture Decision Point 문제 목록

## 1. 목적

이 문서는 `01_시스템_개요.md`, `02_설계_범위_모듈.md`와
`후보구조_작성규칙.md`를 기준으로 구조적 문제를 먼저 식별하고 문제별 DP 문서의
범위와 선행 관계를 정리한다. 발표자료와 `old/` 아래의 기존 결론은 후보 선정의
근거로 사용하지 않았다.

## 2. 공통 baseline

- Host Application과 Host kernel을 포함한 Linux Host는 비신뢰다.
- pKVM/EL2와 TEE는 trust anchor이며 EL2 TCB는 작게 유지한다.
- Linux native와 GlobalPlatform 호환 경계를 유지한다.
- 검증 범위는 Camera→AI의 2-domain pipeline이다.
- 단일 Context Camera/AI HW는 배타적으로 사용한다.
- revoke, drain, reset, zeroize, S2MPU update, regrant 순서는 공통 안전 계약이다.
- 검증된 Workload만 실행한다.
- bulk persistent data는 Host UFS에 ciphertext로 두며 현재 RPMB는 사용하지 않는다.
- 미승인 성능·복구·자원 수치는 `TBD` 또는 `확인 필요`로 둔다.

## 3. 선정 방법

각 항목은 다음 조건을 모두 만족할 때 DP로 선정했다.

1. 같은 문제와 baseline에서 정확히 두 구조 후보를 만들 수 있다.
2. 후보의 책임, 실행 위치, 신뢰 경계 또는 자원 소유권이 달라진다.
3. 후보 사이에 실제 품질속성 trade-off가 있다.
4. Framework 범위 안의 결정이며 제품이나 라이브러리 선택이 아니다.
5. 다른 DP 결과와 2×2로 독립 조합할 수 없으면 선행 관계나 하위 결정으로 병합한다.

## 5. 조사로 추가되거나 보강된 문제

01·02 문서의 모듈 책임을 외부 공식 자료의 기술 제약과 대조해 다음 문제를
보강했다. 외부 자료는 기존 결론의 정답이 아니라 feasibility와 누락 확인에만
사용한다.

- pKVM memory share와 device DMA 격리 제약은 DP-08~11의 feasibility gate다.
- Host scheduler가 pVM 가용성을 좌우할 수 있다는 제약은 DP-15의 feasibility gate다.
- encrypted volume만으로 rollback을 막을 수 없다는 제약은 DP-14의 공통 gate다.
- pVM instance에 결합된 측정과 sealing state는 DP-03·04·14의 검증 입력이다.
- 호출 path identity와 FF-A memory permission은 DP-12의 검증 입력이다.

공식 조사 자료:

- [AOSP AVF architecture](https://source.android.com/docs/core/virtualization/architecture)
- [AOSP AVF security](https://source.android.com/docs/core/virtualization/security)
- [Linux kernel pKVM documentation](https://docs.kernel.org/next/virt/kvm/arm/pkvm.html)
- [GlobalPlatform TEE Client API](https://globalplatform.org/specs-library/tee-client-api-specification/)
- [GlobalPlatform TEE Internal Core API](https://globalplatform.org/specs-library/tee-internal-core-api-specification/)

## 6. 독립 DP로 만들지 않은 항목

| 항목 | 처리 | 이유 |
|---|---|---|
| resource별 ABI를 하나로 합칠지 여부 | DP-09, DP-11, DP-15의 하위 결정 | authority와 신뢰 경계를 정한 뒤 결정할 interface 구조다. |
| frame별 mapping과 resident ring | DP-08의 하위 결정 | backing owner와 pool 선택 뒤 정할 mapping lifetime 정책이다. |
| buffer descriptor join/timeout format | DP-10의 하위 결정 | control request route를 정한 뒤 정의할 protocol이다. |
| HW reset/zeroize 순서 | 공통 baseline | 두 후보가 모두 지켜야 할 안전 gate다. |
| N-domain graph와 미래 HW abstraction | 범위 밖 | 현재 검증은 Camera→AI 2-domain과 Camera/AI HW에 한정된다. |
| guest OS와 filesystem 제품 선택 | 범위 밖 | 책임·신뢰 경계가 아니라 제품 선택이다. |
| 성능 수치와 별점 | 평가 보류 | 승인된 QAS와 예산이 없다. |

## 7. 작성 및 결정 상태

모든 개별 문서는 **후보 작성** 상태다. 두 후보의 구조와 동작까지만 작성했으며
수치 평가, 별점과 최종 결정은 작성하지 않았다. 선행 DP가 확정되지 않았으므로
후행 문서의 endpoint는 논리 이름으로만 표현한다.
