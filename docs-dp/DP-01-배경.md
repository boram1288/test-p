# DP-01. pVM 실행 흐름의 격리 경계 — 배경

## 슬라이드 목적

여러 pVM을 동시에 운용할 때 한 pVM의 멈춤과 crash가 다른 pVM으로 전파되는 문제와, 이를 막기 위한 실행 경계 설계가 cold start 성능에 미치는 영향을 설명한다.

## 핵심 메시지

> pVM별 장애 전파를 차단하면서 cold start p95 2초 이하를 만족하는 Host 실행 경계가 필요하다.

## 현재 구조

- 비신뢰 Host의 한 관리 프로세스가 Secure Camera pVM과 Secure AI pVM의 생성, 제어와 실행을 함께 담당한다.
- 공용 실행 흐름이 두 pVM의 요청 분배, 상태와 자원 관리를 함께 수행한다.
- pKVM은 pVM별 메모리와 생명주기를 격리하지만, Host 관리 프로세스의 실행 흐름까지 분리하지는 않는다.

### 현재 구조 표현 요소

```text
비신뢰 Host
└─ Host Application
   └─ 공용 Framework 프로세스
      ├─ Camera pVM 실행 흐름
      └─ AI pVM 실행 흐름

신뢰 경계
├─ Camera pVM
├─ AI pVM
└─ EL2 격리 집행
```

## 문제 상황

### 장애 전파

- 한 pVM의 worker가 멈추거나 잘못 동작하면 공용 실행 흐름을 점유할 수 있다.
- 공용 실행 흐름이 막히면 다른 pVM의 요청 처리도 중단될 수 있다.
- 공용 관리 프로세스가 crash하면 모든 pVM의 제어가 함께 중단될 수 있다.
- AVL-01은 장애 전파로 인한 Host와 다른 pVM의 다운타임 0을 요구한다.

### 시작 성능

- pVM 미생성 상태의 시작 요청부터 첫 프레임까지가 cold start 측정 구간이다.
- 프로세스 생성, IPC와 공용 자원 경합은 cold start 예산을 사용한다.
- PERF-07은 cold start p95 2초 이하를 요구한다.

```text
시작 요청 → 프로세스 생성 → IPC → pVM 시작 → 첫 프레임
```

## 설계 범위

### 고정 Baseline

- pKVM의 pVM 메모리 격리
- pVM별 생명주기
- pVM 자체의 격리 방식
- pVM 생성 시점

### Project-custom

- Host 실행 흐름의 분리 경계
- pVM별 상태와 자원 관리 책임의 배치
- 한 프로세스 안의 실행 Context로 나눌지, 프로세스 경계로 나눌지에 대한 선택

### 하위 결정

- 장애 후 자원 회수 범위
- CPU 배치

## 품질속성 제약

| 품질속성 | 요구사항 | 설계에 미치는 영향 |
|---|---|---|
| 가용성(AVL-01) | 장애 전파로 인한 Host/다른 pVM 다운타임 0 | hang과 crash의 격리 범위를 정해야 한다. |
| 성능(PERF-07) | cold start p95 2초 이하 | 프로세스 생성, IPC와 자원 경합 비용을 제한해야 한다. |
| 가용성(AVL-04) | 반복 장애 주입 뒤 잔여 자원 0건 | 실패한 실행 흐름의 자원 소유자와 회수 책임을 명확히 해야 한다. |

## 결정 질문

> pVM 실행 흐름을 한 프로세스 안에서 VM별 실행 컨텍스트로 격리할 것인가, 제어기와 VM별 실행 프로세스로 분리할 것인가?

## 슬라이드 하단 문구

> pVM별 멈춤과 crash의 전파를 차단하면서 cold start p95 2초 이하를 만족하는 실행 경계가 필요하다.
