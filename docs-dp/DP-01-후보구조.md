# DP-01. pVM 실행 흐름의 격리 경계 — 후보구조

## 슬라이드 목적

Host의 pVM 실행 흐름을 나누는 두 후보를 실행 위치, 책임, 장애 격리 범위와 cold start 비용 관점에서 비교한다.

## 후보 A. 단일 프로세스 안 VM별 실행 컨텍스트 분리

### 구조

- 비신뢰 Host의 단일 Framework 프로세스에서 모든 pVM을 관리한다.
- 공용 제어기가 요청 분배와 worker 감시를 담당한다.
- Camera Context와 AI Context가 각자의 queue, 상태, handle과 논리적 자원 원장을 관리한다.
- pVM과 EL2의 보호 경계는 변경하지 않는다.

```text
Host Application
└─ 단일 Framework 프로세스
   ├─ 공용 제어기
   │  ├─ 요청 분배
   │  └─ worker 감시
   ├─ Camera Context ── Camera pVM
   └─ AI Context ────── AI pVM
                         └─ EL2 격리 집행
```

### 동작

1. 공용 제어기가 요청을 pVM별 queue에 넣는다.
2. 각 worker가 자신의 pVM 상태와 자원 원장만 갱신한다.
3. 공용 제어기가 worker hang을 감지하면 해당 Context의 신규 요청을 차단한다.
4. 공용 제어기가 해당 pVM의 자원 회수를 요청한다.
5. 공용 프로세스가 crash하면 모든 Context의 제어가 함께 중단될 수 있다.

### 장점

- 별도 프로세스 생성과 IPC가 필요하지 않다.
- 시작 경로가 단순해 cold start 성능에 유리하다.
- pVM별 queue와 상태를 논리적으로 분리할 수 있다.

### 단점과 확인 사항

- 공용 프로세스 crash를 pVM별로 격리할 수 없다.
- worker hang이 공용 제어기까지 점유하는 경우를 검증해야 한다.
- AVL-01의 Host/다른 pVM 다운타임 0 충족 여부가 확인 필요다.

## 후보 B. 제어기와 VM별 실행 프로세스 분리

### 구조

- 비신뢰 Host에 제어 프로세스와 pVM별 실행 프로세스를 둔다.
- 제어 프로세스는 정책, 요청 분배와 실행 프로세스 감시를 담당한다.
- Camera 실행 프로세스와 AI 실행 프로세스가 각 pVM의 생명주기, 상태, handle과 자원 원장을 관리한다.
- Host 내부에 프로세스 경계를 추가하지만 보안 신뢰 경계는 계속 pVM/EL2에 둔다.

```text
Host Application
└─ 제어 프로세스
   ├─ IPC ── Camera 실행 프로세스 ── Camera pVM
   └─ IPC ── AI 실행 프로세스 ────── AI pVM
                                      └─ EL2 격리 집행
```

### 동작

1. 제어 프로세스가 요청을 대상 실행 프로세스로 IPC 전달한다.
2. 실행 프로세스가 해당 pVM의 생명주기와 자원 원장을 갱신한다.
3. 제어 프로세스가 OS 프로세스 상태로 실행 프로세스의 hang/crash를 감지한다.
4. 실패한 실행 프로세스를 격리하고 해당 pVM의 자원 회수를 시작한다.
5. 실행 프로세스를 다시 생성해 기존 제어 계약에 연결한다.

### 장점

- 실행 프로세스의 hang과 crash를 pVM별로 격리할 수 있다.
- 실패 단위와 자원 회수 범위가 명확하다.
- 한 실행 프로세스의 장애가 다른 pVM의 제어 흐름에 미치는 영향을 줄인다.

### 단점과 확인 사항

- cold start 경로에 프로세스 생성과 IPC가 추가된다.
- 프로세스 종료 감지와 EL2/커널 강제 회수 연계가 필요하다.
- PERF-07의 cold start p95 2초 이하 충족 여부를 측정해야 한다.

## 후보 비교

### 필수 Gate

| 품질속성 | 기준 | 후보 A | 후보 B | 판단 근거 |
|---|---|---|---|---|
| 가용성(AVL-01) | 장애 전파로 인한 Host/다른 pVM 다운타임 0 | 확인 필요 | 통과 예상 | 후보 A는 공용 프로세스 crash가 전체 제어에 영향을 줄 수 있다. 후보 B는 실행 프로세스 crash를 pVM별로 제한한다. |

### 잠정 평가

| 평가 항목 | 후보 A | 후보 B | 평가 이유 |
|---|---:|---:|---|
| 가용성(AVL-01) | ★★☆ | ★★★ | 프로세스 경계는 hang과 crash를 함께 격리한다. |
| 성능(PERF-07) | ★★★ | ★★☆ | 후보 B는 cold start 경로에 프로세스 생성과 IPC를 추가한다. |

## 핵심 트레이드오프

- 후보 A는 시작 경로가 짧지만 공용 프로세스 crash를 격리하지 못하면 AVL-01 gate를 통과할 수 없다.
- 후보 B는 pVM별 crash 격리로 가용성이 높지만 프로세스 생성과 IPC로 cold start 비용이 증가한다.

> 격리 강도를 높이면 가용성은 향상되지만 프로세스 생성과 IPC로 cold start 비용이 증가한다.

## 검증 항목

| 검증 항목 | 측정 방법 | 합격 기준 |
|---|---|---|
| 장애 전파 | 각 pVM worker/process에 hang과 crash를 주입하고 Host와 다른 pVM의 가동 상태를 측정 | AVL-01: Host/다른 pVM 다운타임 0 |
| cold start | pVM 미생성 상태에서 시작 요청부터 첫 프레임까지 p95를 측정 | PERF-07: p95 2초 이하 |
| 회수 연계 | 장애 뒤 원장과 실제 자원을 대조 | AVL-04: 반복 장애 주입 뒤 잔여 자원 0건 |

## 슬라이드 구성 제안

- 상단: AVL-01과 PERF-07 요구사항 표시
- 중앙: 후보 A와 후보 B의 구조 다이어그램을 좌우 배치
- 하단 1: 후보별 장점과 단점
- 하단 2: 필수 gate, 잠정 별점과 핵심 트레이드오프
- 상태 표기: 평가 중이며 특정 후보를 선택 표시하지 않음
