# 설계 범위 모듈

## 1. 목적

이 문서는 01_시스템_개요.md에 정의된 시스템 목적, 기능, 신뢰 원칙, 제약사항과
구현 범위를 설계 책임 단위로 구체화한다.

설계 범위는 M-01부터 M-12까지 12개의 배치 중립적 논리 모듈로 구성한다.

## 2. 모듈 구성 원칙

- 모듈은 Framework가 설계 책임을 지는 응집된 논리 책임과 상태의 묶음이다.
- Host, pVM, protected service pVM, EL2와 TEE는 모듈이 아니라 실행/격리/신뢰
  배치 경계다.
- 하나의 논리 모듈은 실행 경계에 따라 둘 이상의 컴포넌트로 분해될 수 있다.
- 비신뢰 Host에서 실행되는 컴포넌트도 Framework 범위에 포함될 수 있다.
- 보호 자원의 최종 허가와 실제 권한 상태는 보호 경계에서 확인한다.
- 외부 platform/HW를 직접 만들지 않더라도 interface, adapter, lifecycle과
  접근 제어 계약은 Framework 설계 범위에 포함한다.
- 현재 구조와 검증 topology는 Camera→AI의 2-domain pipeline으로 한정한다.

## 3. 실행 경계와 구현 범위

| 실행/자원 경계 | Framework가 설계하는 부분 | 직접 구현하지 않는 부분 |
|---|---|---|
| 비신뢰 Host Linux | Framework process, 관리 API, relay, UFS storage backend, pVM/HW 제어 kernel driver와 상태 관리 | Linux OS, Host Application과 UFS 물리 장치 |
| pVM Guest | measured bootstrap, Workload 실행 계약과 buffer/TEE/storage/HW guest adapter | Camera/AI Workload 업무 로직과 guest OS 제품 |
| pKVM/EL2 | hypercall/ABI, Stage-2와 자원별 protected enforcement 연동 및 검증된 최소 extension | pKVM 자체 포팅과 일반 Hypervisor core 개발 |
| protected service pVM | policy, buffer, HW 또는 QoS authority를 배치하는 경우의 service와 protocol | 고정 platform으로 사전 확정된 공통 service pVM |
| TEE/Secure OS | pVM adapter, caller binding, key seal/unseal, session과 shared resource lifecycle | 신규 Secure OS와 TA 제품 기능의 처음부터의 개발 |
| Camera/AI HW, S2MPU, CPU/memory와 UFS | 할당/회수/격리 adapter, native driver 배치와 Framework 통합 계약 | HW IP, S2MPU, 저장 매체와 register/firmware의 물리 설계 |

pKVM 자체 포팅은 범위 밖이지만 pKVM interface와 자원별 enforcement 연동은 범위
안이다. EL2 extension은 작은 TCB를 유지하고 platform owner 확인과 feasibility
검증을 통과하는 경우에만 사용한다.

Embedded SoC의 CPU, memory, 전력과 UFS 용량은 유한하다. TEE에는 직접 소유하는
영구 저장장치가 없고 할당 memory도 작으므로 실행에 필요한 최소 key/state만
유지한다. Secure OS가 암호 키를 봉인해 만든 ciphertext key blob은 Host의
Secure OS Adapter를 통해 UFS에 기록하고, 복원 시 같은 경로로 TEE에 전달한다.
평문 암호 키는 REE, Secure OS Adapter와 UFS에 노출하지 않는다.

## 4. 설계 범위 모듈

| ID | 논리 모듈 | 범위 안의 핵심 책임 | 책임 경계 |
|---|---|---|---|
| M-01 | Framework API / Request Gateway | Host Application의 pipeline 시작/종료, pVM lifecycle과 Workload 탑재 요청을 공통 request로 정규화하고 대상 모듈로 route한다. public façade, version/capability와 오류 계약을 제공한다. | guest 내부 요청을 받거나 최종 보안 허가를 판정하지 않는다. |
| M-02 | pVM Lifecycle Manager | pVM generation별 create/start/stop/delete, request queue, handle, lifecycle ledger와 할당 자원 회수를 관리한다. | pVM 실행 수명과 failure containment 단위를 관리한다. |
| M-03 | Multi-pVM Orchestrator | Camera/AI 2-domain의 dependency, pipeline epoch, endpoint bind/rebind와 service-ready 순서를 관리한다. | 일반화된 N-domain graph는 다루지 않는다. |
| M-04 | Fault/Recovery Manager | failure 단위 recovery transaction을 열고 자원별 회수 완료 상태를 모아 재시작/rebind 또는 fail-closed 종료를 판정한다. | 실제 HW, buffer, session, CPU와 memory 권한은 자원별 모듈이 회수한다. |
| M-05 | Workload Loader / Verifier | package image, manifest, signature, version과 freshness를 검증하고 동일 byte/generation에 결합된 executable 상태와 verified identity를 만든다. | 검증 실패 또는 identity 불일치 시 Workload를 실행하지 않는다. |
| M-06 | Protected Policy Authority | verified subject, action, resource, context와 policy version으로 최종 allow/deny를 판정하고 decision/capability 상태를 관리한다. | 비신뢰 Host의 판단을 최종 보안 근거로 사용하지 않으며 실제 자원 상태는 집행 모듈이 관리한다. |
| M-07 | Secure Inter-domain Channel | pVM 간 또는 pVM/Host 간 frame의 request ingress, endpoint, grant, logical lease, buffer ownership, mapping lifetime, join, timeout과 reclaim을 관리한다. | payload와 control metadata를 승인된 도메인에만 노출하고 불필요한 copy를 피한다. |
| M-08 | HW IP Mediation Layer | Camera/AI device generation, physical lease, native driver placement, client job과 revoke→drain/reset/zeroize→regrant 전환을 관리한다. | 단일 Context HW의 배타 사용과 안전한 주체 전환을 보장한다. |
| M-09 | DMA/S2MPU Isolation Controller | policy decision을 Stage-2, S2MPU, MMIO, IRQ, CPU dispatch와 memory mapping 변화로 집행하고 actual-state completion을 반환한다. | buffer/HW/runtime별 adapter와 PEP로 구성되며 단일 중앙 authority를 전제하지 않는다. |
| M-10 | Secure OS Adapter | pVM GlobalPlatform request의 caller identity와 integrity를 TEE까지 보존하고 adapter/dispatch, session, async request와 shared resource lifecycle을 관리한다. TEE의 ciphertext key blob을 Host/UFS 사이에서 전달한다. | 평문 암호 키를 REE에 노출하거나 영속 저장하지 않는다. |
| M-11 | Secure Persistent Storage | pVM보다 오래 유지되는 ciphertext namespace/volume의 create/attach/detach/reconnect/reclaim, UFS I/O, quota, retention, 공간 부족 처리와 Workload identity/metadata binding을 관리한다. | 유한한 UFS 용량을 관리하며 TEE의 key seal/unseal과 session lifecycle은 담당하지 않는다. |
| M-12 | Runtime Resource / QoS Authority | pVM generation별 CPU time과 memory capacity의 admission, min/max entitlement, reservation 또는 lease 상태와 stop/fault reclaim을 관리한다. | Host scheduler/allocator는 실행 mechanism이며 최종 protected entitlement를 판정하지 않는다. |

## 5. 범위 밖과 경계 interface

| 직접 구현하지 않는 대상 | 범위 안에 남는 interface/책임 |
|---|---|
| Host Application | M-01의 관리 API, identity와 authorization request 계약 |
| Camera/AI Workload 업무 로직 | M-05의 package/bootstrap과 M-07/M-08/M-10/M-11 guest adapter 계약 |
| Linux와 guest OS 제품 자체 | Host process/kernel driver와 guest adapter의 Linux native interface |
| pKVM 자체 포팅과 일반 Hypervisor core | hypercall/ABI, Stage-2와 자원별 PEP 연동 및 조건부 최소 extension |
| 신규 Secure OS와 TA 제품 기능 | 기존 Secure OS의 pVM adapter, caller binding, key blob과 session lifecycle 연동 |
| Camera/AI HW, S2MPU와 UFS 물리 설계 | M-08/M-09의 할당/회수/격리 및 M-10/M-11의 UFS 저장 계약 |
| 특정 guest OS/RTOS/unikernel 제품 선택 | 실행 환경과 무관한 Framework/guest contract |
| 미래 HW class의 범용 SoC abstraction | 현재 Camera/AI HW integration |
| fleet OTA, fleet SLA/MTBF와 상용 운영 체계 | 단일 device의 local 검증/계측 interface |
| 일반화된 N-domain pipeline | 현재 Camera→AI 2-domain pipeline |

격리, 권한 전환, data path, 장애 회수와 성능 증거는 별도 핵심 모듈로 분리하지 않고
각 모듈의 identity/generation/trace 기반 검증 contract에 포함한다.
