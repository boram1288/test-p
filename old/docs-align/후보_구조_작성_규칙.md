# 후보 구조 작성 규칙

## 1. 후보 구성 원칙

1. 후보 구조는 정확히 2개로 작성한다.
2. 두 후보는 아키텍처 구조를 바꾸는 서로 다른 답이어야 한다.
3. 후보별 책임과 실행 위치가 달라야 한다.
4. 품질속성 간 트레이드오프가 명확해야 한다.
5. 하나의 후보가 모든 품질속성에서 우월하면 후보 간 Decision Point로 보지 않는다.
6. 과제 범위 안에서 결정할 수 있는 구조만 다룬다.
7. 구현 라이브러리나 제품 선택은 후보 구조의 차이로 만들지 않는다.
8. 다른 Decision Point의 세부 구현은 하위 결정으로 둔다.
9. 검증 방법만 다른 경우에는 별도 후보로 만들지 않는다.
10. 후보별 세부 동작과 평가는 각각 `후보별 동작 구조`와 `품질속성 비교`에서 작성한다.

## 3. 후보 구조에 포함할 내용

- 후보 이름은 구조적 차이를 드러내야 한다.
- 각 컴포넌트의 실행 위치를 명시한다.
- 각 컴포넌트의 책임을 명시한다.
- 후보 A와 후보 B를 각각 설명하는 구조 다이어그램을 반드시 포함한다.
- 두 후보구조간 비교가 가능한 장점, 단점을 명시한다.

## 4. 후보 구조 다이어그램 작성 규칙

- 후보 A와 후보 B에 각각 하나의 PlantUML 다이어그램을 작성한다.
- 다이어그램은 `plantuml` 코드 블록으로 작성한다.
- 두 다이어그램은 같은 관점, 추상화 수준과 흐름 방향을 사용한다.
- 공통 컴포넌트는 두 다이어그램에서 같은 이름, 색상과 표기 방식을 사용한다.
- 각 컴포넌트의 실행 위치와 책임을 표시한다.
- 신뢰 주체, 비신뢰 주체와 신뢰 경계를 구분한다.
- 결정 대상 자원의 소유 주체와 장애·종료 시 회수 주체를 표시한다.
- 두 후보에서 달라지는 책임, 실행 위치, 신뢰 경계 또는 자원 소유권이 시각적으로 드러나야 한다.
- 결정 질문과 무관한 구현 상세나 아직 정하지 않은 하위 결정을 추가하지 않는다.
- 다이어그램의 구성 요소와 흐름은 후보 구조 및 후보별 동작 구조의 설명과 일치해야 한다.

## 5. 작성 후 점검

1. 두 후보가 같은 문제와 같은 범위를 다루는가?
2. 두 후보의 구조적 차이가 책임, 실행 위치, 신뢰 경계으로 설명되는가?
3. 두 후보 사이에 실제 품질속성 트레이드오프가 있는가?
4. 후보별 설명과 다이어그램의 구성 요소, 흐름 및 책임이 일치하는가?
