# fscrypt 동작 방식

## 개요

`fscrypt`는 Linux 파일시스템이 파일과 디렉터리를 암호화할 때 사용하는 커널 기능이다. 커널 코드는 주로 `fs/crypto/`에 있으며, 파일시스템이 이 기능을 연결해 사용한다. `ext4`, `F2FS` 등이 대표적으로 `fscrypt`를 지원한다.

`fscrypt`라는 이름은 다음 두 대상을 가리킬 수 있다.

| 구분 | 역할 |
|---|---|
| 커널 `fscrypt` | 파일시스템 안에서 파일 내용과 이름을 실제로 암복호화하는 기능 |
| 사용자 영역 `fscrypt` 도구 | 암호화 설정, 키 등록과 해제를 편리하게 수행하는 명령줄 도구 |

이 문서에서는 커널 `fscrypt`를 중심으로 설명한다.

## 동작 위치

`fscrypt`는 블록 장치 전체가 아니라 파일시스템 계층에서 동작한다.

```text
응용프로그램
    ↓ 파일 읽기·쓰기
파일시스템
    ↓
fscrypt
    ↓ 암호문 블록
Linux 블록 계층
    ↓
저장장치
```

응용프로그램은 일반적인 파일 API를 그대로 사용한다. 올바른 키가 등록되어 있으면 파일시스템이 읽을 때 복호화하고 쓸 때 암호화한다.

## 암호화 정책 적용 단위

`fscrypt`는 암호화 정책을 디렉터리에 설정한다. 정책에는 다음 정보가 포함된다.

- 파일 내용 암호 방식
- 파일 이름 암호 방식
- 정책 버전
- 기준 키를 찾기 위한 식별자
- 파일별 암호 처리 방법을 정하는 선택값

정책이 설정된 디렉터리에서 새로 만들어지는 파일과 하위 디렉터리는 그 정책을 이어받는다. 이미 자료가 들어 있는 디렉터리에 나중에 정책을 적용하는 방식은 지원되지 않으므로 일반적으로 빈 디렉터리에서 시작한다.

## 보호하는 정보

`fscrypt`가 주로 보호하는 정보는 다음과 같다.

- 일반 파일의 내용
- 파일과 디렉터리 이름
- 심볼릭 링크의 대상 경로

키가 없으면 파일 내용은 암호문으로 보인다. 파일 이름도 원래 이름 대신 암호화된 형태로 보이거나 접근이 제한된다.

## 보호하지 않는 정보

`fscrypt`는 파일시스템의 모든 관리 정보를 암호화하지 않는다. 다음 정보는 저장장치에서 확인될 수 있다.

- 파일 크기
- 파일 수와 디렉터리 구조의 일부
- 파일 소유자와 접근 권한
- 생성·수정·접근 시각
- 파일이 저장된 블록 위치
- 파일 접근 순서와 횟수
- 암호화 정책과 키 식별에 필요한 공개 정보

따라서 `fscrypt`는 파일 내용과 이름의 비밀성을 제공하지만 파일시스템 전체의 형태와 사용 흔적까지 숨기지는 않는다.

## 키 구조

### 기준 키

암호화된 디렉터리 묶음은 기준 키 하나에 연결된다. 사용자 영역의 키 관리 프로그램은 커널의 `FS_IOC_ADD_ENCRYPTION_KEY` 요청을 사용해 이 키를 등록할 수 있다.

기준 키는 암호화 정책과 연결된다. 하나의 기준 키가 여러 디렉터리를 보호할 수 있지만, 서로 분리해야 하는 자료에는 별도의 키를 사용하는 것이 일반적이다.

### 파일별 키

일반 정책에서는 `fscrypt`가 기준 키와 각 파일의 임의 값으로 파일별 키를 만든다.

```text
기준 키
  + 파일별 임의 값
        ↓ 키 생성 함수
파일 내용용 키
파일 이름용 키
그 밖의 내부 키
```

파일마다 다른 키를 만들거나, 선택한 정책에 따라 같은 기준 키를 사용하는 파일들이 내용용 키를 공유할 수 있다. 암호 방식과 키 생성 방법은 정책 버전과 선택값에 따라 달라진다.

### 키 식별자

정책에는 기준 키 원문이 아니라 키 식별자가 기록된다. 파일시스템은 이 식별자로 현재 등록된 키를 찾는다. 키 식별자는 키를 찾기 위한 값이며 암호 키 자체가 아니다.

## 파일 쓰기 과정

1. 응용프로그램이 암호화 정책이 설정된 디렉터리의 파일에 평문을 쓴다.
2. 파일시스템이 해당 파일의 정책과 기준 키를 찾는다.
3. `fscrypt`가 파일 내용에 사용할 키와 암호 처리 정보를 준비한다.
4. 커널 암호 기능 또는 저장 암호 장치가 파일 내용을 암호화한다.
5. 파일시스템이 암호문 블록을 저장장치에 기록한다.
6. 파일 이름도 파일 이름용 키로 암호화하여 파일시스템 관리 정보에 기록한다.

파일시스템에 따라 암호화 결과를 임시 페이지에 만든 뒤 저장하거나, 블록 요청에 암호 정보를 붙여 저장 암호 장치에 전달할 수 있다.

## 파일 읽기 과정

1. 응용프로그램이 파일 열기를 요청한다.
2. 파일시스템이 디렉터리의 암호화 정책과 키 식별자를 확인한다.
3. 필요한 기준 키가 커널에 등록되어 있는지 확인한다.
4. 저장장치에서 암호문 블록을 읽는다.
5. `fscrypt`가 파일 내용용 키로 암호문을 복호화한다.
6. 파일시스템이 평문을 응용프로그램에 반환한다.

키가 없으면 원래 파일 이름으로 파일을 찾거나 파일 내용을 읽을 수 없다.

## 파일 이름 처리

파일 내용과 파일 이름은 서로 다른 용도이므로 별도의 키를 사용한다. 디렉터리에서 파일을 찾으려면 검색할 평문 이름을 같은 방식으로 암호화한 뒤 저장된 이름과 비교해야 한다.

파일 이름 길이는 파일시스템이 허용하는 최대 길이의 영향을 받는다. 암호화된 이름을 키 없이 표시해야 할 때는 파일시스템이 표시 가능한 형태로 바꾸어 보여 줄 수 있다.

## 커널 암호 처리

기본 방식에서는 Linux 커널의 암호 기능이 파일 내용을 암복호화한다. 이 경우 현재 사용하는 기준 키나 기준 키에서 만든 키가 커널 메모리에 존재할 수 있다.

키를 커널에서 제거하면 이후의 새 접근을 막을 수 있다. 다만 이미 열려 있던 파일, 메모리에 남은 평문 페이지와 사용 중인 객체가 즉시 모두 사라진다고 가정해서는 안 된다. 키 제거 뒤의 접근 차단과 메모리 정리는 별도로 확인해야 한다.

## inline encryption

지원되는 파일시스템과 저장장치에서는 `fscrypt`가 파일 내용 암복호화를 저장 암호 장치에 맡길 수 있다. 이를 `inline encryption`이라고 한다.

```text
fscrypt
    ↓ 블록 요청에 암호 정보 추가
blk-crypto
    ↓
저장 암호 장치의 키 슬롯
    ↓
저장 또는 읽기 중 암복호화
```

`ext4`와 `F2FS`에서는 `inlinecrypt` 마운트 선택값으로 이 경로를 요청할 수 있다. 저장장치가 필요한 암호 방식이나 처리 단위를 지원하지 않으면 커널 암호 처리로 돌아갈 수 있다.

## 하드웨어로 감싼 키

저장 암호 장치가 하드웨어로 감싼 키를 지원하면 실제 파일 내용용 키가 일반 커널 메모리에 평문으로 나타나지 않도록 할 수 있다.

```text
하드웨어로 감싼 키
        ↓ 저장 암호 장치 내부에서 해제
파일 내용용 키
        ↓
저장 암호 장치의 키 슬롯
```

이 방식에도 다음 제한이 있다.

- 지원하는 저장 암호 장치와 `inline encryption` 경로가 필요하다.
- 장치가 지원하는 암호 정책만 사용할 수 있다.
- 파일 내용용 키는 보호할 수 있지만 파일 이름용 키를 만드는 데 사용하는 소프트웨어 비밀값은 커널 메모리에 존재할 수 있다.
- 해당 저장 암호 장치에 묶이므로 다른 장치로 파일시스템을 옮기는 일이 어려울 수 있다.

## 보안 범위

`fscrypt`는 주로 올바른 키가 없는 상태에서 저장된 파일 내용과 이름을 읽지 못하게 하는 기능이다.

다음 상황은 `fscrypt`만으로 막을 수 없다.

- 올바른 키가 등록된 상태에서 허가된 과정이 평문을 읽는 경우
- 공격자가 실행 중인 커널을 완전히 장악한 경우
- 커널의 평문 페이지나 응용프로그램 메모리를 읽는 경우
- 파일 크기, 시각과 접근 모양 같은 암호화되지 않은 정보를 관찰하는 경우
- 저장된 암호문을 삭제하거나 오래된 파일시스템 전체로 바꾸는 경우

또한 `fscrypt`의 기본 목적은 비밀성이다. 저장 자료의 모든 변경을 인증하거나 최신 버전임을 보장하는 기능은 별도로 구성해야 한다.

## 핵심 정리

- `fscrypt`는 Linux 파일시스템 안에서 동작하는 파일 단위 암호화 기능이다.
- 응용프로그램은 일반 파일 API를 그대로 사용한다.
- 암호화 정책은 디렉터리에 설정되고 새 하위 파일과 디렉터리에 이어진다.
- 파일 내용, 파일 이름과 심볼릭 링크 대상을 보호한다.
- 파일 크기, 권한, 시각과 접근 모양 등은 숨기지 않는다.
- 기준 키에서 파일 내용용 키와 파일 이름용 키 등을 만든다.
- 기본 방식에서는 사용 중인 키가 커널 메모리에 있을 수 있다.
- `inline encryption`을 사용하면 파일 내용 암복호화를 저장 암호 장치에 맡길 수 있다.
- 하드웨어로 감싼 키는 파일 내용용 키의 커널 노출을 줄이지만 모든 `fscrypt` 내부 비밀값을 보호하지는 않는다.
- 암호문 변경 인증과 최신 버전 확인은 `fscrypt`의 기본 기능이 아니다.
